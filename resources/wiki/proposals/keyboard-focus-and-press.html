1. Keyboard focus on every control, and a press that gives

Status: done · Author’s approval: proposal ☑ plan ☑

Why

Today the keyboard only reaches text fields: Tab goes from one field to the next, and buttons, check boxes and choices can only be used with a pointer. That breaks the first rule of an accessible interface, that the keyboard reaches everything. Bubble 4 has also settled how focus and pressing should look (focus lights the control’s own edge; a control shrinks a little while pressed), and go-ui should let a design system ask for that through its theme, as it already does for colours and corners.

Out of scope

  • Arrow keys inside lists, menus and grids: Tab reaches the list, and moving inside it is a later proposal.
  • Changes for screen readers: they already have their own focus (SetScreenReaderFocus).
  • Animating the press: it shrinks while held and comes back, with no tween, until go-ui has one.

Design

  • Who has the keyboard: the program decides, through one field on the context:
    • KeyboardNavigation: WhenGiven (the default, chosen by the author: if a program forgets to choose, the worst case is that Tab does not walk the buttons, not that a game stops answering): the interface has the keyboard only while a field is typed in, a modal layer (dialog, sheet, menu) is open, or the program calls TakeKeyboard(). Escape, or ReleaseKeyboard(), gives it back. A click on a button does not take the keyboard, so Space in a game never presses the last button clicked.
    • KeyboardNavigation: Always: for programs that are only an interface (a register, a settings app). Tab always moves the focus.
    • While the interface has the keyboard, go-ui claims it in the input state, as fields do today, so go-renderer’s viewer and a game’s own controls know to stay quiet. Otherwise it claims nothing and reads no key.
  • Cost: the focus order is a slice of IDs kept on the context and reset to length zero each frame, so it allocates nothing once warm; nothing is added to it while the interface does not have the keyboard. The ring is one stroke, only on the focused control. The press scales one element while it is held. Moving the focus changes the drawing, so it redraws; a still interface with no keys pressed draws nothing new, as today.
  • Focus order: every pressable control and every field joins a list in drawing order, each frame. The tabFrom and tabBack that fields already use move over that list instead of the fields alone. The focus stays an ID, so it survives from frame to frame as it does today.
  • Keyboard or pointer: keyboardFocus is the control Tab reached; any press of the pointer clears it, so the ring (painted only on it) shows only for focus from the keyboard, which is what CSS calls :focus-visible. A click remembers its control, and Tab goes on from it.
  • Theme tokens, all zero for go-ui’s own look:
    • FocusWidth: the ring’s width. Zero keeps today’s 3 pixels.
    • FieldFocusEdge: when true, a field colours its border with FocusRing and draws no ring.
    • PressScale: how big a held control is drawn (0.97 in Bubble). Zero means it doesn’t change.
    • The ring of a control filled with Primary is drawn inside it in OnPrimary, always: a ring in FocusRing could not be told from the fill.
  • Less motion: go-renderer’s input state does not carry the platform’s setting yet, so a LessMotion field on the context lets the program say so.
  • Painting: the ring is one more Rectangle stroke in paint.go, from the element’s rectangle and corner. The press scales the element’s rectangle around its centre before painting it and its children, so text and icons shrink with it.
  • Not taken: rings that follow the browser’s look with a gap. Bubble chose an edge with no gap, and a gap only looks right on the page’s own background.

Result

Built on feature/keyboard-focus, with the adapter in Bubble’s feature/v4. go vet and go test ./... pass in both, with no display.

The review found, and these were fixed:

  • Tab from a field to a button lost the focus in WhenGiven. A Tab that moves the focus now keeps the keyboard until Escape or a click.
  • Space on a game’s Resume button also reached the game. HasKeyboard() now stays true for the rest of a frame in which the interface used a key.
  • The docs claimed less cost than measured.
  • Tab started from the top after a control went away, or after a click.
  • Every held control shrank; now only buttons do, as in Bubble’s CSS.

Not done, for a person to check on screen:

  • R7’s pixel-by-pixel comparison of cmd/app captures. The register’s tests pass, but it now sets Always, so no capture was compared.
  • R8’s showcase beside the browser.
  • T9’s register audit benchmarks: only the 300-control benchmark was measured.
  • How the ring and the press look in a real window, with a keyboard and a touch screen.
