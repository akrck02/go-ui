Get started

This page takes you from nothing to a window with a button that works, in about fifteen minutes. You need to know a little Go; you need no experience with interfaces.

What you will do

  1. Install Go and a C compiler, which the window needs.
  2. Get Go UI and Go Renderer, side by side, and run an example.
  3. Write your first interface.

⚠️ Go UI is an educational project and its API still changes. Pin the commits you build against.

1. Install the tools

You need Why How
Go 1.25 or later The language go.dev/dl, then go version
A C compiler The desktop window is opened through cgo Linux: gcc; macOS: xcode-select --install; Windows: MinGW-w64 on the PATH
OpenGL 4.1 headers (Linux) What draws on Linux and Windows; macOS draws through Metal Debian, Ubuntu: sudo apt install libgl1-mesa-dev xorg-dev

The library itself is pure Go: only programs that open a window need cgo. Tests do not, so go test ./... runs anywhere.

2. Get the code

Go UI draws through Go Renderer, which Go downloads like any other module, at the version go.mod names:

git clone https://github.com/akrck02/go-ui
cd go-ui
go run ./cmd/app

A whole desktop application opens: a menu bar, a toolbar with a search box, a list, a table and an inspector. Try go run ./cmd/app -dark, and the other examples:

Example Shows
go run ./cmd/app A desktop application with no 3D at all
go run ./cmd/example Panels over a 3D scene
go run ./cmd/scene-app An application layout around a 3D view
go run ./cmd/workbench A grouped table, chips, a menu, a sheet, drag and drop
go run ./cmd/plan-editor Editing a 3D scene: placing huts on an island’s map

💡 No display? Add -capture shot.png to draw one frame into a picture; on a server, run it under xvfb-run.

3. Your first interface

Make a module of your own and ask for Go UI, which brings Go Renderer with it:

mkdir lighthouse && cd lighthouse
go mod init example.com/lighthouse
go get github.com/akrck02/go-ui@latest

💡 Changing Go UI or Go Renderer at the same time? Clone them beside your module and join the three with a workspace (go work init . ../go-ui ../go-renderer): Go then builds against your copies instead of the versions.

main.go:

package main

import (
	"log"

	ui "github.com/akrck02/go-ui"
	"github.com/akrck02/go-ui/window"
)

func main() {
	lit := false // your data lives in your variables

	err := window.Run(window.Options{Title: "Lighthouse"}, func(context *ui.Context) {
		context.Heading("North Point")
		if context.PrimaryButton("Switch") { // true on the frame it is clicked
			lit = !lit
		}
		if lit {
			context.Label("The lamp is lit.")
		}
	})
	if err != nil {
		log.Fatal(err)
	}
}

go mod tidy
go run .

Click the button: the line appears and goes. That is the whole idea of Go UI, called immediate mode:

  • The function you give window.Run describes the interface, and runs again whenever something happens: a click, a key, the window resized.
  • A control is a function call. A button returns true on the frame it is clicked; there are no button objects to create, keep or wire with callbacks.
  • Your variables are the truth. Showing something is an if, a list is a for, and the screen can never show a stale value.

Between frames the window sleeps: an idle Go UI program uses no processor.
